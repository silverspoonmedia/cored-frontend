# Localization (i18n)

SPA-side localization: two locale files, lazy chunks, RTL plumbing, and the guard chain. Normative rules: [.cursor/rules/i18n-locales.mdc](../.cursor/rules/i18n-locales.mdc) + the always-on [.cursor/rules/i18n-guardrail.mdc](../.cursor/rules/i18n-guardrail.mdc). Backend rules, canonical locale list: `cored-backend/docs/platform/localization.md`; settled terms and the domain glossary: `cored-backend/docs/platform/naming-conventions.md`.

| Need | Path |
|------|------|
| Locale files | `src/i18n/locales/{en,id}.json` — core only; `en` is the source and the only eager chunk |
| Feature packs | `src/i18n/features/{name}/{en,id}.json` — a product's keys, loaded lazily by its `FeatureModule.messages` and deep-merged over the core pack (`src/features/messages.ts`); core copy never names a product |
| Pack loader | `src/i18n/featurePacks.ts` — the cycle-free seam: `./index` reads the eager English pack and the per-locale pack from here, and a feature composable reads copy through `useI18n()`, so `i18n → registry → feature → i18n` never evaluates a half-built instance |
| Shared instance + helpers | `src/i18n/index.ts` (`ensureLocale`, `translatableValue`, `normalizeTranslatableMap`, `RTL_LOCALES`) |
| Curation log | `src/i18n/curation-log.json` — one entry per curated key (`curated_at`, `surface`, `source`) |
| Duplicate-English policy | `scripts/lib/duplicate-english-allowlist.mjs` (locale-scoped) |
| Guard chain | `npm run check:i18n` → `check-i18n.mjs` + `check-i18n-usage.mjs` + `check-curation-log.mjs` |
| Cross-repo guards | `cored-backend/scripts/locale-{pack-parity,flat-pack-parity,glossary-scan,prose-scan,rawkey-scan}.php` |

## In one screen

- **Patch keys, never dump files.** Grep the key in the core `en.json` or the owning `features/{name}/en.json`, patch both files of that pack, run `npm run check:i18n` (it reads both trees) and `npm run check:features` (a pack missing a locale fails).
- A key whose surface lives in a feature belongs in that feature's pack — moving it to core forces every fork to carry copy it cannot render.
- `check:i18n` proves parity, placeholders, duplicates and curation-log validity — it never proves the translation reads well. Read the changed string back on its own surface (register, calque, false friend, filler) before finishing.
- A key referenced from code but defined in no locale is a hard failure; unreachable keys are deleted, not kept — sweep them in the same change as the screen removal.
- `RTL_LOCALES` is empty, so every shipped locale stamps `html[dir="ltr"]`. The direction pipeline (split CSS entries, `vendor-rtl.css`, reload-after-persist) stays wired so re-adding a right-to-left language is one list edit.
- Mirrored packs (`validation`, `http-statuses`, `auth`, `passwords`, `pagination`) must match the backend exactly, sigil aside. The SPA `actions.*` block is deliberately not a mirror.
- Cross-repo guards live in `cored-backend` and cannot run in a lone SPA checkout — run `php artisan test --filter=Locale` from the checkout this repo is the sibling of when a mirrored pack or glossary term moves.

## Tooling

| Script | Purpose |
|--------|---------|
| `node scripts/i18n-pair-dump.mjs <locale> [--ns=<prefix>]` | Read-only `key \t EN \t <locale>` dump for review batches |
| `node scripts/apply-translations.mjs <locale> <map.json> [--surface=…] [--source=…] [--dry-run]` | Applies a batch and appends the curation-log entries (`leaf` for literal dotted settings labels) |
| `node scripts/i18n-duplicate-report.mjs` | Writes `i18n-duplicate-report.json`: inventory, classifications, stale-allowlist detection; `actionable_pairs` must stay 0 |
| `npm run check:i18n:usage` | Usage check alone — every literal `t()`/`tm()`/`te()` key under `src/**` resolves in `en.json` |
