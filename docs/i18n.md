# Localization (i18n)

SPA-side localization contract. Backend PHP locale rules and the canonical supported-locale list: `monolith/docs/platform/localization.md`. SPA/backend key mapping: [conversion rules](#conversion-rules) below; contract pointer: `monolith/docs/integration/vue-workers-spa.md#i18n-porting-notes`.

**Agent: never `Read` a whole locale JSON file.** Each of `src/i18n/locales/{en,id,ja,ko,zh-CN,ar,ru}.json` is thousands of lines. Grep the key in `en.json`, `StrReplace` (or equivalent) the same key in all seven files, then run `npm run check:i18n`. English is the source; other locales are patched, not dumped into context.

## Locales

Seven locales: `en` (reference/source), `id`, `ja`, `ko`, `zh-CN`, `ar`, `ru`. Files: `src/i18n/locales/{en,id,ja,ko,zh-CN,ar,ru}.json`. `LOCALE_LABELS` supplies native language names in the switcher. SPA `zh-CN` maps to canonical backend `zh_CN` through the `X-SPA-Locale` header; all other codes map one-to-one.

### Conversion rules

| Laravel PHP | vue-i18n JSON |
|-------------|---------------|
| `lang/{locale}/web/settings.php` | `web.settings.*` (`zh_CN` ↔ `zh-CN` at API/browser boundary) |
| `lang/{locale}/ui.php` | `ui.*` |
| `trans('web/settings.title')` | `t('web.settings.title')` — `.` separator, not `/` |
| `:variable` placeholder | `{variable}` placeholder |
| `trans_choice('key', count)` | `t('key', { count })` |

**Translatable payload maps** (API fields like menu `name`/`description`) are keyed by the **backend** code: send `zh_CN`, never `zh-CN` — the backend rejects unknown keys ("The selected name.zh-CN is invalid"). `FormTranslatableInput` normalizes both directions through the helpers beside the shared i18n instance in `src/i18n/index.ts`: `translatableValue()` resolves a backend-keyed prefill (`zh_CN`) for the row rendered under the SPA code (`zh-CN`), `normalizeTranslatableMap()` emits the backend key and drops aliases, and submit paths re-normalize as defense in depth. Only the row label shows the SPA code; the model stays backend-keyed throughout the edit. Display columns use the server-resolved string (`row.name`), which needs no conversion. Covered by `tests/translatableLocaleMap.test.ts`.

**Every translation change updates all seven locale files in one change** (patch the key in each file; do not load the files wholesale). Translate contextually, not literally: review surface (button, heading, table, status, toast, validation, error, explanatory copy), audience, domain glossary, placeholders, plural rules, and locale-specific register. Preserve technical identifiers and English machine-contract text. Split keys when one phrase needs different contexts.

## RTL / direction

`ar` sets `html[dir="rtl"]`; all other locales force `ltr`. The global CSS entry is direction-split: `main.ts` awaits `src/assets/main-ltr.css` or `src/assets/main-rtl.css` (picked from the detected locale before mount). `main-rtl.css` imports `vendor-rtl.css`, a sibling of `vendor.css` that swaps Bootstrap/AdminLTE for their official `.rtl` dist builds — a separate CSS entry, **not** a Vite `resolveId` alias (Vite runs CSS `@import` through postcss, so a resolver-based swap no-ops in production builds); keep both vendor files' import lists in sync.

Switching locale across directions reloads the page (`setLocale()` → `location.reload()`) so the other stylesheet loads; never hot-swap direction without reload. The reload must run only **after** `auth/locale` persists — `setLocale(locale, { reload: false })` skips it and `AppNavbar.switchLocale()` awaits the persist + `refetchNavigation()` before calling `reloadForDirection()` last; a synchronous reload inside `setLocale()` aborts the in-flight persist and leaves the dynamic menu on the old locale.

## Locale chunk loading

Only `en.json` ships in the eager bundle (fallbackLocale must always resolve). The other six locales load on demand: `src/i18n/index.ts` maps each non-`en` locale to a dynamic `import()` (`LAZY_LOCALES`), and `ensureLocale()` awaits the chunk and calls `setLocaleMessage()` before `i18n.global.locale` switches. First switch to a locale pays one chunk fetch; repeat switches are cached by both Rollup (module cache) and vue-i18n (installed messages). Locale JSONs stay on disk untouched — `check:i18n` parity is unaffected. The RTL direction-change reload re-enters the app and re-resolves the requested locale through the same path.

RTL styles use logical properties (`start`/`end`, `margin-inline-*`, `padding-inline-*`, `inset-inline-*`) with overrides scoped to `html[dir="rtl"]`. Directional icons: glyph swap for `bi-arrow-left` back buttons, `scaleX(-1)` for `.ar-breadcrumb__sep`, `isRtl()`-bound prev/next chevrons, explicit `rtl:rotate-180` variant where meaning changes. AdminLTE's `.nav-arrow` is mirrored by the vendor RTL build itself — never add a custom transform for it (clobbers its `translateY(-50%)` centering). AdminLTE and Valkivid3 rules stay namespace-scoped.

## Guards

Run before review (CI runs it before `build-only`):

```sh
npm run check:i18n
```

The checker (`scripts/check-i18n.mjs`) validates locale key parity, Vue interpolation placeholders, malformed braces, exact English duplicates, and suspicious hardcoded user-facing fallback copy. Exact duplicates fail unless their complete key appears in the explicit allowlist; entries are limited to brands, provider/code identifiers, `QRIS`, `Discord`, `vTual`, `Microstock`, machine-contract text, and **locale loanwords** (keys whose accepted term in the locale IS the English word — Indonesian IT vocabulary like `Status`, `Filter`, `Checkout`, `Settlement`; Chinese `Slug`). Prefer a natural native term when one exists; allowlist only the loanword a native user would actually read in a shipped product.

`node scripts/i18n-duplicate-report.mjs` writes `i18n-duplicate-report.json` — a locale/namespace/key-level inventory with classifications, placeholder tokens, actionable totals, and stale-allowlist detection. Inventory never authorizes untranslated user-facing copy. Per-locale/two-segment-namespace counts support file-by-file translation waves (backend side: `php scripts/backend-locale-audit.php` + `scripts/locale-report-query.php` in Monolith).

## Usage rules

- `useI18n()` only works inside component `setup()` (or composables called synchronously from setup). Router guards, stores, shell hydration, realtime callbacks, and module-level services must import the shared `src/i18n` instance and call `i18n.global.t(...)` — otherwise initial navigation fails with `Must be called at the top of a setup function`.
- Use `computed()` or active translators for labels and option arrays that must update after runtime locale switching.
- Format user-facing numbers/dates with `Intl.NumberFormat(locale.value)` / `Intl.DateTimeFormat(locale.value, …)`; never unqualified `toLocaleString()`. API `*_formatted` / `*_human` companions remain authoritative when present.
- API messages take priority; fallback errors use locale keys (`src/i18n/fallbacks.ts` — centralized generic transport fallbacks).
- Settings field labels: `web.settings.fields` / `hints` are literal dotted JSON keys — look up via `tm()` + `rt()`, never `t('web.settings.fields.' + key)` (vue-i18n splits on `.` and misses the literal key).
- `main.ts` reports router errors with `router.onError()` and mounts immediately so a failed initial navigation cannot leave a blank document; protected components still wait for auth hydration through the route guard.
