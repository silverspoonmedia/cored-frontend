# Localization (i18n)

SPA-side localization contract. Backend PHP locale rules and the canonical supported-locale list: `monolith/docs/platform/localization.md`. SPA/backend key mapping: [conversion rules](#conversion-rules) below; contract pointer: `monolith/docs/integration/vue-workers-spa.md#i18n-porting-notes`.

**Agent: never `Read` a whole locale JSON file.** Each of `src/i18n/locales/{en,id,ja,ko,zh-CN,ar,ru}.json` is thousands of lines. Grep the key in `en.json`, `StrReplace` (or equivalent) the same key in all seven files, then run `npm run check:i18n`. English is the source; other locales are patched, not dumped into context.

## Locales

Seven locales: `en` (reference/source), `id`, `ja`, `ko`, `zh-CN`, `ar`, `ru`. Files: `src/i18n/locales/{en,id,ja,ko,zh-CN,ar,ru}.json`. `LOCALE_LABELS` supplies native language names in the switcher. SPA `zh-CN` maps to canonical backend `zh_CN` through the `X-SPA-Locale` header; all other codes map one-to-one.

### Conversion rules

| Laravel PHP | vue-i18n JSON |
|-------------|---------------|
| `lang/{locale}/web/settings.php` | `web.settings.*` (`zh_CN` ↔ `zh-CN` at API/browser boundary) |
| `lang/{locale}/ui.php` | `ui.*` |
| `trans('web/settings.title')` | `t('web.settings.title')` — `.` separator, not `/` |
| `:variable` placeholder | `{variable}` placeholder |
| `trans_choice('key', count)` | `t('key', { count })` |

**Translatable payload maps** (API fields like menu `name`/`description`) are keyed by the **backend** code: send `zh_CN`, never `zh-CN` — the backend rejects unknown keys ("The selected name.zh-CN is invalid"). `FormTranslatableInput` normalizes both directions through the helpers beside the shared i18n instance in `src/i18n/index.ts`: `translatableValue()` resolves a backend-keyed prefill (`zh_CN`) for the row rendered under the SPA code (`zh-CN`), `normalizeTranslatableMap()` emits the backend key and drops aliases, and submit paths re-normalize as defense in depth. Only the row label shows the SPA code; the model stays backend-keyed throughout the edit. Display columns use the server-resolved string (`row.name`), which needs no conversion. Covered by `tests/translatableLocaleMap.test.ts`.

**Every translation change updates all seven locale files in one change** (patch the key in each file; do not load the files wholesale). Translate contextually, not literally: review surface (button, heading, table, status, toast, validation, error, explanatory copy), audience, domain glossary, placeholders, plural rules, and locale-specific register. Preserve technical identifiers and English machine-contract text. Split keys when one phrase needs different contexts.

## RTL / direction

`ar` sets `html[dir="rtl"]`; all other locales force `ltr`. The global CSS entry is direction-split: `main.ts` awaits `src/assets/main-ltr.css` or `src/assets/main-rtl.css` (picked from the detected locale before mount). `main-rtl.css` imports `vendor-rtl.css`, a sibling of `vendor.css` that swaps Bootstrap/AdminLTE for their official `.rtl` dist builds — a separate CSS entry, **not** a Vite `resolveId` alias (Vite runs CSS `@import` through postcss, so a resolver-based swap no-ops in production builds); keep both vendor files' import lists in sync.

Switching locale across directions reloads the page (`setLocale()` → `location.reload()`) so the other stylesheet loads; never hot-swap direction without reload. The reload must run only **after** `auth/locale` persists — `setLocale(locale, { reload: false })` skips it and `AppNavbar.switchLocale()` awaits the persist + `refetchNavigation()` before calling `reloadForDirection()` last; a synchronous reload inside `setLocale()` aborts the in-flight persist and leaves the dynamic menu on the old locale.

## Locale chunk loading

Only `en.json` ships in the eager bundle (fallbackLocale must always resolve). The other six locales load on demand: `src/i18n/index.ts` maps each non-`en` locale to a dynamic `import()` (`LAZY_LOCALES`), and `ensureLocale()` awaits the chunk and calls `setLocaleMessage()` before `i18n.global.locale` switches. First switch to a locale pays one chunk fetch; repeat switches are cached by both Rollup (module cache) and vue-i18n (installed messages). Locale JSONs stay on disk untouched — `check:i18n` parity is unaffected. The RTL direction-change reload re-enters the app and re-resolves the requested locale through the same path.

RTL styles use logical properties (`start`/`end`, `margin-inline-*`, `padding-inline-*`, `inset-inline-*`) with overrides scoped to `html[dir="rtl"]`. Directional icons: glyph swap for `bi-arrow-left` back buttons, `scaleX(-1)` for `.ar-breadcrumb__sep`, `isRtl()`-bound prev/next chevrons, explicit `rtl:rotate-180` variant where meaning changes. AdminLTE's `.nav-arrow` is mirrored by the vendor RTL build itself — never add a custom transform for it (clobbers its `translateY(-50%)` centering). AdminLTE and Valkivid3 rules stay namespace-scoped.

## Guards

Run before review (CI runs it before `build-only`):

```sh
npm run check:i18n
```

That script chains three checks:

```sh
node scripts/check-i18n.mjs && node scripts/check-i18n-usage.mjs && node scripts/check-curation-log.mjs
```

- `check-i18n.mjs` — parity, interpolation tokens, malformed braces, placeholders glued to a preceding character (a literal colon rewritten to the placeholder sigil), English duplicates, hardcoded fallback copy.
- `check-i18n-usage.mjs` (`npm run check:i18n:usage` runs it alone) — every literal `t()`/`tm()`/`te()`/`$t()` key under `src/**/*.{ts,vue}` resolves in `en.json`. A key referenced from code but present in **no** locale is a hard failure: `fallbackLocale: en` cannot rescue it, so the user sees the raw key. Keys assembled at runtime (`t(\`status_${state}\`)`) are reported informationally by static prefix only, never as failures.
- `check-curation-log.mjs` — every entry in `src/i18n/curation-log.json` must reference a key that exists in `en.json`, carry a parseable ISO8601 timestamp, and leave no stale entries behind when a key is deleted.

**Unreachable keys are deleted, not kept.** `check-i18n-usage.mjs` proves every key *code* references exists; nothing proves the reverse, so a key that no call site can reach is invisible to every gate. The Blade→SPA migration left 344 such `web.vtual*` keys (whole `web.vtual.claims.*`, `web.vtual.credentials.*`, `web.vtual.admin.*`, `web.vtual.confirm.*`, `web.vtual.ajax.*`, `web.vtual.table.*` subtrees, plus scattered leftovers like `public.live_now.heading` and `public.profile.stat_channels`) across all seven files. They were removed in the 2026-09-24 closure wave, together with the containers they left empty and the 23 allowlist entries that went stale as a result.

The 2026-09-25 wave repeated the sweep with two additions: it pruned the dead `web.vtual.admin.credentials.intro.steps` container (three empty objects that survived the first pass because the container itself still resolved), and it **repointed the `source` field of the curation log** — 579 entries named files that no longer exist (`VkStr1LiveNow.vue`, `VkStr1VtuberDirectory.vue`, `src/views/vtual-public/**`, and locale tokens written as `en.js`). A stale `source` is not cosmetic: the whole point of the field is that a later reviewer can open the consuming surface, so a broken path makes the entry unverifiable and the key effectively un-reviewed. `check-curation-log.mjs` validates key existence and timestamps, **not** path existence — if you move or delete a consuming file, fix its entries by hand in the same change.

When you remove a screen or a component, sweep its keys in the same change:

1. Flatten `en.json` and keep the keys under the namespace you touched.
2. Build the set of reachable keys from **every** repo file except `src/i18n/` — `src/**` is not enough, because a route `titleKey` lives in `src/router/routes/*.ts` and a doc may be the only remaining reference. Match with a boundary (`(?![A-Za-z0-9_.-])`), or `web.vtual.status` will be "found" by `web.vtual.status_label`.
3. Treat `t(\`prefix_${x}\`)` and `t('prefix_' + x)` as making the whole `prefix_` subtree reachable — a false keep is cheap, a false delete ships a raw key.
4. Delete from all seven files, prune the containers left empty, then drop the now-stale allowlist entries and the curation-log entries. `node scripts/i18n-duplicate-report.mjs` prints the stale-allowlist list.
5. `npm run check:i18n` must stay green; the report's `actionable_pairs` must stay `0`.

`check:i18n` is per-repo: it compares the seven locale files against each other and against `src/`, and it cannot see the backend. Four defects it structurally cannot catch are guarded in the **Monolith** repo, and they read these SPA locale files as one of their surfaces:

| Guard (Monolith `scripts/`) | Class it closes |
|---|---|
| `locale-prose-scan.php` | English left inside translated prose. `check-i18n.mjs` skips a value the moment it differs from `en`, so `Nama management wajib diisi.` passed every SPA check. `id` is scanned for the domain terms whose settled rendering is a different word (`management`→`manajemen`, `role`→`peran`, `creator`→`kreator`); `ja`/`ko`/`zh-CN`/`ar`/`ru` for any Latin word of 3+ letters inside target-script text. Allowlist: `monolith/scripts/lib/locale-latin-allowlist.php`. |
| `locale-rawkey-scan.php` | A translation **value** that is itself a dotted/slashed key path — a raw key rendered to the user. |
| `locale-pack-parity.php` | The SPA `validation.*`, `http-statuses.*`, `auth.*`, `passwords.*`, `pagination.*` blocks are copies of the backend packs, with `:attr` ↔ `{attr}` as the only allowed difference. |
| `locale-glossary-scan.php` | A settled term reverted to a banned variant, or a term's occurrence floor collapsing. |

Each exits 1 when it finds something, and each **exits 1 when the sibling repo is not checked out** rather than reporting success — a guard that cannot see half its input must say so. None of the four is wired into the **`locale`** CI job: that job runs only the checks that need one repo, so it carries no cross-repo token. Run them from a Monolith checkout that has this repo as a sibling, via `php artisan test --filter=Locale` (which shells out to all six guards and asserts exit 0). When the sibling is absent, `LocaleGuardTest` asserts each cross-repo guard fails loudly and then reports it as **skipped**, so a green run cannot be mistaken for "all six ran". The backend workflow's second job, `backend`, runs the whole `php artisan test` suite — including `tests/Domain/**`, which the `locale` job never touched.

A consequence worth knowing: **a pull request that only touches this repo is not gated by these four.** `npm run check:i18n` is per-repo and cannot see the backend, and the backend workflow triggers on backend changes. If a batch touches a mirrored pack (`validation`, `http-statuses`, `auth`, `passwords`, `pagination`) or a settled glossary term, run `php artisan test --filter=Locale` from the backend checkout before merging.

The readability half — register, surface, calque, false friend, filler — is judgment, not a script. The checklist is in `monolith/docs/platform/localization.md` under [Curation tooling → Readability checklist](../monolith/docs/platform/localization.md); the AI-facing rule is `.cursor/rules/i18n-guardrail.mdc`.

The checker (`scripts/check-i18n.mjs`) validates locale key parity, Vue interpolation placeholders, malformed braces, placeholders glued to a preceding character, exact English duplicates, and suspicious hardcoded user-facing fallback copy. Exact duplicates fail unless `isDuplicateEnglishAllowed(key, locale)` returns true.

That rule lives in **`scripts/lib/duplicate-english-allowlist.mjs`** and is **locale-scoped**, because whether an English word is the right term is a property of one language, not of a key. A flat key-only list silences every locale at once — that is how `ko.ui.copyright` and `zh-CN.web.vtual.public.title` stayed English while both were "allowlisted". The module exports two lists:

- `globalDuplicateEnglishKeys` — identical in every locale by design: brand and product names (`Archivd`, `Microstock`, `vTual`, `Discord`, `QRIS`, `iPaymu`, `Midtrans`, the marketplace names), platform type names (`LIVE`/`VOD`), machine-contract text (probe method names, `sha256`, `{count} / 2000`, `YYYY-MM-DD`, `{current} + {purchase} = {total}`, URL/UUID placeholders) and universal acronyms (`URL`, `UUID`, `N/A`, `OK`, `API`).
- `localeDuplicateEnglishKeys` — keys whose accepted term in **that** locale is the English word. Today only `id` needs it (bahasa gaul IT: `Status`, `Filter`, `Model`, `Margin`, `Label`, `Avatar`, `Channel`, `Platform`, `Gateway`, `Slug`, `Navbar`, `Sidebar`, `Checkout`, `Upgrade`, `Downgrade`, `Addon`, `Host`, `Marketplace`, `Token`, `API key`, `Access token`, `Refresh token`, `Client secret`, `Email`, `Bank`, `Audio`, `Video`, `Thumbnail`, `Subtotal`, `Total`, `Settlement`, `Folder`). `ja`, `ko`, `zh-CN`, `ar`, and `ru` have an empty list: **any** English carryover there is a hard failure.

Prefer a natural native term when one exists; allowlist only the loanword a native user would actually read in a shipped product, and only for the locale that needs it. Both `check-i18n.mjs` and `i18n-duplicate-report.mjs` import this module, so the checker and the report cannot drift apart again.

Recent additions (do not re-litigate): `web.vtual.public.profile.filter_type_live` / `filter_type_vod` — the platform's own type names, matching the already-allowlisted `profile.live` / `profile.vod` — and `web.vtual.public.profile.filters_label` — the Indonesian loanword `Filter`, consistent with `validation.attributes.filter`. Anything else in the vTual filter bar is translated normally.

`node scripts/i18n-duplicate-report.mjs` writes `i18n-duplicate-report.json` — a locale/namespace/key-level inventory with classifications, placeholder tokens, actionable totals, and stale-allowlist detection, and prints a warning when `actionable_pairs` is non-zero. Inventory never authorizes untranslated user-facing copy. Per-locale/two-segment-namespace counts support file-by-file translation waves (backend side: `php scripts/backend-locale-audit.php` + `scripts/locale-report-query.php` in Monolith). Like the backend audit, the report is a manual review artifact, not a CI step.

## Curation log and tooling

JSON locales cannot carry comments, so every curated SPA key is recorded in **`src/i18n/curation-log.json`** — a sidecar deliberately kept **outside** `src/i18n/locales/` so it never ships in a locale chunk and never affects parity checks:

```json
{
  "version": 1,
  "updated_at": "2026-09-21T16:54:35+07:00",
  "locales": {
    "id": {
      "api.activity-log.events.field_decrypted": {
        "curated_at": "2026-09-21T16:09:15+07:00",
        "surface": "API success/error toast + validation message",
        "source": "backend /api/v1 responses consumed via src/composables"
      }
    }
  }
}
```

`surface` names the UI surface the string renders in (toast, inline error, status badge, table header, label, explanatory copy) and `source` the consuming file. Both exist so a later reviewer can re-judge the wording without re-reading the app. Log a key only when you actually reviewed its consuming surface; `check-curation-log.mjs` enforces key existence and timestamp validity, not review quality.

Per-locale coverage: `id`, `ja`, `zh-CN`, `ar`, `ko`, and `ru` completed the full contextual wave on both sides, so every supported locale has had one. The authoritative per-locale status, the curated-flag counts, and the term-drift list live in `monolith/docs/platform/localization.md` — Coverage status and Domain glossary.

"Completed the full wave" is not the same as "closed". The closing pass settled the framework packs and the flat pack for `id`, `ja`, `zh-CN`, and `ar`, so all six non-`en` locales now report **0** on both cross-repo guards: `locale-pack-parity.php` (framework packs) and `locale-flat-pack-parity.php` (the flat `lang/{locale}.json` pack against its canonical PHP owners). See the parity table and the flat-pack mirror policy in the backend localization doc.

The `ko` wave also settled two conventions the SPA side needs:

- **Register.** Instructions, hints, and empty states use 해요체 (`-하세요`); statements and toasts keep 합쇼체 (`-합니다`, `-되었습니다`). Do not collapse the two into one level — see the register note in the backend localization doc.
- **Placeholder particles.** Never glue a particle to a `{placeholder}` when the substituted value's final consonant is unknown (`{product}가`). Use the parenthesised form (`{product}이(가)`, `{field}을(를)`) or reword so the placeholder is not the token before the particle. Invariant particles (`의`, `에`) are fine attached.

The `ru` wave settled three conventions the SPA side needs:

- **Date columns are nouns, not participles.** A table header or detail label uses `Дата создания` / `Дата изменения` / `Дата удаления` / `Дата начала`, and an expiry column uses `Действует до`. The participle forms (`Создано`, `Изменено`, `Истекает`) read as a sentence fragment agreeing with a noun the header does not have. `validation.attributes.created_at` / `updated_at` / `deleted_at` keep `создано в` / `обновлено в` / `удалено в`, because those are interpolated into validation sentences rather than used as labels.
- **`checkout` and `billing` are different words.** `оформление заказа` for the checkout flow, `оплата` for billing; `канал оплаты` is drift from `платёжный канал`, while `Способ оплаты` is the correct rendering of `Payment method` and is not the same concept as a channel.
- **No `Пожалуйста` filler.** The imperative alone carries the politeness (`Выберите другой.`), and the filler is banned by the glossary scan. `вы` stays lowercase except at sentence start.

Settled terms are enforced, not just documented. `php scripts/locale-glossary-scan.php` in the Monolith repo scans the SPA locale files too (alongside the backend ones), failing on a forbidden variant (`공개 설정`, `가시성`, `마이크로스톡`, `프로브` for `ko`; `биллинг`, `зонд`, `менеджмент`, `сеанс`, `канал оплаты`, `Пожалуйста`, `Панель администратора` for `ru`; `Dilarang`, `Tidak Diizinkan`, `Kadaluwarsa`, `Identitas URL` for `id`; `クレーム`, `点検` for `ja`; `子弹`, `凭据`, `套餐`, `档案`, `登出`, `显示所有`, `喜欢` for `zh_CN`; `ذهب`, `سبيكة`, `عذراً`, `الإنتقال`, `الإستضافة`, `الإيميل` for `ar`) or when a settled term's occurrence count falls below its floor. The `id`/`ja`/`zh_CN`/`ar` maps were added by the closing pass, each floor taken from a measured count. `npm run check:i18n` cannot see either class: the value is non-English, the key exists, and the braces balance. The `ko` wave's first `visibility` pass was recorded as done while eleven SPA values still said `공개 설정` — that scan is what caught it. Run it after any batch that touches a glossary term.

The SPA `validation.*` and `http-statuses.*` namespaces are copies of the backend `lang/{locale}/*.php` packs, and `auth.*`, `passwords.*`, and `pagination.*` are small framework messages kept in step the same way. A validation error can be rendered from either side depending on where the request was rejected, so both copies must carry the same wording for the same key, differing only in the placeholder sigil (`:attribute` in PHP, `{attribute}` in vue-i18n). `php scripts/locale-pack-parity.php [locale]` in the Monolith repo is the standing guard: it diffs the mirrored packs both ways, normalizing the sigil, `{'@'}`, and HTML entities, and exits non-zero while any locale diverges. All six locales are at 0. Two cautions from the `ko` wave: re-run the guard instead of trusting the number recorded in the doc (the `ar` row claimed 0 for a session while the guard reported 1 — the missing `validation.attributes.h-captcha-response` label), and when you add or fix a key on one side of a mirrored pack, fix the other side in the same change.

The flat `lang/{locale}.json` pack is guarded the same way, by `php scripts/locale-flat-pack-parity.php [locale]` in the Monolith repo. Every scalar is classified against `lang/en/**/*.php`: an **owned** scalar (189 of 228) must equal its canonical owner's value for that locale, and an **unowned** one (39, package chrome with no PHP counterpart) is curated independently. The SPA is not compared against it — the pack is backend package chrome — but a change to a backend namespace that owns a scalar is a change the pack has to follow in the same commit, which is what the guard enforces. All six locales are at 0.

The SPA `actions.*` block is **not** a mirror of the backend `actions.php` pack. It is the SPA's own shared action vocabulary, curated against its own surfaces, and it legitimately differs: `ja` uses 操作 where the pack says アクション, `ar` uses الإجراءات where the pack says إجراءات, and `ko` uses the bare noun (추가, 취소) where the pack uses the `-하기` form (추가하기, 취소하기). Syncing it from the pack regresses the SPA button register — the `ko` wave did that once and reverted it.

### Placeholder hazards the guards cannot see

A literal colon in copy that is not a Laravel placeholder becomes a vue-i18n interpolation when the batch is ported. `web.payments.channels.empty` shipped `php artisan payments{sync}-routing-policy` for every locale — the `:sync` of the artisan command name had been rewritten to `{sync}` during the `:attr` → `{attr}` migration, so vue-i18n tried to interpolate a variable that never exists and rendered the command name wrong. `check-i18n.mjs` cannot catch that with its other rules: the braces are balanced, the key exists in all seven files, and the token is not in `en.json`'s placeholder set. It now has a dedicated rule — `gluedPlaceholder()`, `/[A-Za-z0-9]\{[A-Za-z_]/`, which is never valid vue-i18n — so the regression fails the guard instead of shipping. When porting backend copy, check every colon that is part of a command, URL, or time: it must stay a literal `:`, and vue-i18n only needs `{'@'}` escaping for a literal `@`.

## Usage rules

- `useI18n()` only works inside component `setup()` (or composables called synchronously from setup). Router guards, stores, shell hydration, realtime callbacks, and module-level services must import the shared `src/i18n` instance and call `i18n.global.t(...)` — otherwise initial navigation fails with `Must be called at the top of a setup function`.
- Use `computed()` or active translators for labels and option arrays that must update after runtime locale switching.
- Format user-facing numbers/dates with `Intl.NumberFormat(locale.value)` / `Intl.DateTimeFormat(locale.value, …)`; never unqualified `toLocaleString()`. API `*_formatted` / `*_human` companions remain authoritative when present.
- API messages take priority; fallback errors use locale keys (`src/i18n/fallbacks.ts` — centralized generic transport fallbacks).
- Settings field labels: `web.settings.fields` / `hints` are literal dotted JSON keys — look up via `tm()` + `rt()`, never `t('web.settings.fields.' + key)` (vue-i18n splits on `.` and misses the literal key).
- `main.ts` reports router errors with `router.onError()` and mounts immediately so a failed initial navigation cannot leave a blank document; protected components still wait for auth hydration through the route guard.
